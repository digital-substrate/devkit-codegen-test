# runtime — the viper C++ runtime, stubbed

The hand-written references under `*/target/hand/` are compiled, and compiling them needs
the runtime they are written against. These headers are that runtime, reduced to the
declarations the references touch.

**Their signatures are copied from `com.digitalsubstrate.viper/src/Viper`, not invented.**
That is the whole value of them: a reference written against an imagined runtime proves
nothing. When one of these drifts from the real header, the exercise is worth nothing, so
the rule is to copy rather than to design.

Two exceptions, each marked in the file that carries it:

- `Viper_Codec.hpp` — `Writer`, `Reader` and `tag<T>` are generated by the pack today, not
  part of the runtime. They are here because the design implies they should be: the pack
  generates them only because their methods are named per type, and free functions found by
  argument-dependent lookup leave the classes with nothing model-specific in them.
- `Viper_Hash.hpp` — the accumulator-first shape. `hash(x)` on a fundamental type cannot
  work, since a fundamental type has no associated namespace and lookup never leaves the
  unit; a runtime-typed first argument restores it, exactly as the Writer does for `write`.

Shared by every model's reference, so one `-I` reaches them from anywhere:

```sh
clang++ -std=c++20 -fsyntax-only -I. -I../../../runtime *.cpp
```
